2. Arquitetura

O navegador baixa o frontend (nginx) e fala só com o Gateway, por HTTPS. O Gateway confere o JWT e o papel, valida o JSON e chama os microsserviços por gRPC sobre HTTP/2, levando a chave interna. O Pedidos chama o Catálogo para conferir e precificar os itens. Os dados ficam no Cloud SQL (PostgreSQL 16), acessado pelo conector do Cloud Run; senhas e chaves vêm do Secret Manager.

3. Cliente: do login ao pedido

No celular

O mesmo frontend em 390 px de largura: abas que rolam de lado e ficam fixas no alto, pratos em cartões e a linha do tempo do pedido, sem rolagem lateral da página.

4. Chrome DevTools: tudo por HTTPS, só com o Gateway

Painel Network do Chrome DevTools ligado à aba do frontend durante o fluxo da seção 3. As chamadas de dados vão para delivery-gateway-j76gmjruwa-uc.a.run.app por HTTPS; o navegador nunca fala com os microsserviços. Antes de cada chamada com token o navegador faz o preflight de CORS, que o Gateway libera só para a origem do frontend.

5. Cozinha

A conta da cozinha é criada pelo job de migração com a senha do Secret Manager. O Gateway barra com 403 qualquer cliente nessas rotas. Os pedidos abertos aparecem num quadro de comandas, uma coluna por etapa, como nas telas de cozinha dos restaurantes; o tempo de cada comanda na etapa fica verde até 10 min, amarelo até 20 e vermelho depois disso ou se passou da previsão. A tabela continua no modo Lista.

De volta ao cliente: entregue e pedir de novo

A cozinha levou o pedido até Entregue pelos botões das comandas. O cliente vê a linha do tempo completa, com o horário de cada etapa, e pode repetir o pedido: os itens voltam para a sacola, que confere cada um com o cardápio atual (preço, disponibilidade e opção) antes de continuar.

6. Tolerância a falhas no Cloud Run

A falha é provocada pela variável de ambiente FALHA_PERCENTUAL=100 no serviço delivery-catalogo (nova revisão pelo painel ou pelo gcloud run services update), sem mudar código. O Gateway faz o retry, abre o circuito do Catálogo, serve o cardápio salvo e recusa o pedido com 503; Usuários e Pedidos continuam no ar. Ao voltar para 0, tudo se recupera.
